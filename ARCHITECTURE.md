# MasterOps Project Architecture & Directory Map

MasterOps is a DevOps-specific bootstrap framework designed to move a project from "Day 0" (Infrastructure) to "Day 1" (Application Deployment) in minutes.

## 📂 Directory Structure

### 1. CLI & Entry Points
- `/bin/masterops`: The main executable. The entry point for all user commands.
- `/cli/commands/`: Contains the logic for each slash command:
  - `start.sh`: The Framework Wizard (State-aware project bootstrapping).
  - `terraform.sh`: Local infrastructure provisioning.
  - `doctor.sh`: System readiness and health checks.
  - `nginx.sh`: Interactive domain and SSL configuration.
- `/cli/lib/`: Core CLI helper functions:
  - `common.sh`: UI helpers, logging, and confirmation prompts.
  - `state.sh`: The "Brain" — handles Global and Project state using `yq`.
  - `detect.sh`: System capability detection.
- `/lib/`: Shared low-level logic for DB modes, port checking, and selections.

### 2. The Ansible Engine (`/ansible`)
The "Muscle" of the project. Uses a declarative approach to ensure idempotency.
- `site.yml`: The master playbook that orchestrates all roles.
- `/roles/common`: Base system setup (updates, basic packages).
- `/roles/database`: Database engine management.
  - `postgres.yml`, `mysql.yml`, `mariadb.yml`, `redis.yml`: Engine-specific setup.
  - `common_db_setup.yml`: Creates project-specific DBs and users.
- `/roles/backend`: Backend framework scaffolding.
  - `/laravel`: PHP/Composer setup $\rightarrow$ Laravel scaffolding.
  - `/dotnet`: .NET SDK setup $\rightarrow$ API scaffolding $\rightarrow$ Systemd service.
  - `/springboot`: Java/Maven setup $\rightarrow$ Spring Initializr scaffolding.
- `/roles/frontend`: Frontend framework scaffolding.
  - `/react`: Node.js $\rightarrow$ Vite/React scaffolding $\rightarrow$ Build.
  - `/nextjs`: Node.js $\rightarrow$ Next.js scaffolding $\rightarrow$ Build.
  - `/vue`: Node.js $\rightarrow$ Vite/Vue scaffolding $\rightarrow$ Build.
- `/roles/nginx_vhost`: Generates Nginx VirtualHost configs based on the domain.
- `/roles/project`: Handles project-level housekeeping.
  - `tasks/main.yml`: Manages `.env` generation and CI/CD workflow injection.
  - `templates/env.j2`: The master template for application environment files.

### 3. The CI/CD Library (`/templates/github-actions`)
A library of pre-built YAML workflows injected into projects during the `start` command.
- `/backend/{laravel,dotnet,springboot}/main.yml`: Framework-specific build/test/deploy pipelines.
- `/frontend/{react,nextjs,vue}/main.yml`: Frontend build and deploy pipelines.

### 4. Infrastructure as Code (`/terraform`)
- Contains the Terraform modules for AWS:
  - VPC, Subnets, EC2, IAM Roles, S3 Buckets, and Route53.

### 5. Public Assets (`/public`)
- `/src/SystemDesign.png`: The architectural blueprint of the entire workflow.

## 🔄 Data Flow
1. **Input:** `masterops start "project"` $\rightarrow$ `cli/commands/start.sh`
2. **State:** `cli/lib/state.sh` $\rightarrow$ reads `/etc/masterops/state.yaml`
3. **Orchestration:** `ansible/site.yml` $\rightarrow$ reads `vars.yml` generated by the Wizard.
4. **Execution:** Ansible Roles $\rightarrow$ Installs Software $\rightarrow$ Scaffolds Code $\rightarrow$ Configures Nginx.
5. **Completion:** Update project state in `.masterops/state.yaml`.
